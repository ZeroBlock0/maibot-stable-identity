# 稳定身份与原话查证

为 MaiBot 的群聊上下文补充稳定账号身份，帮助模型区分同名用户、识别改过昵称的同一账号，并在需要时回查原始发言。

**作者：Zero · 版本：0.2.6 · 许可证：GPL-3.0-or-later**

这是独立增强插件，不改写原有人设配置或记忆数据库。身份信息会改变模型输入，仍可能影响回复表现；它不能保证模型永不认错人，也不会自动修复旧的错误记忆。

**0.2.6 修复提示词干预过重：**普通聊天不再附加记忆引用缺失状态或记忆核验规则；身份标签缩短为 `sender_id="qq:1001"`，人物 ID 按账号在每个请求内只标一次。身份判定与原话权限不放宽。更新内容见 [CHANGELOG](CHANGELOG.md)，诊断和升级验收见 [运行说明](docs/OPERATIONS.md)。

## 能做什么

| 功能 | 当前行为 |
|---|---|
| 聊天身份标注 | 给 Planner 和 Replyer 上下文中能准确回查的真实消息补充平台、真实用户 ID和宿主人物 ID |
| 同名与改名区分 | 平台＋真实用户 ID作为身份依据；同名不合并，改昵称不拆成新人 |
| 原话查证 | 在当前授权会话内，按账号、人物 ID、关键词、时间或消息 ID查询原始发言 |
| 记忆来源核验 | 对当前上下文中原生记忆、画像工具的结果，利用完整工具记录核验主体和来源；缺失时明确保持未知 |
| 原生功能配合 | 保留原生工具调用、结果配对、多模态内容和记忆读写流程；只增强临时模型请求 |

SnowLuma Adapter 负责把平台消息及发送者 QQ 号上报给 MaiBot；本插件利用宿主保存的这些信息，让模型实际看到并使用账号身份。两者可以配合，职责不同。详见 [SnowLuma 与数据持久化说明](docs/SNOWLUMA_AND_MEMORY.md)。

## 安装、升级与启用

### 首次安装

1. 将安装包中的 `stable_identity/` 放入当前 MaiBot 实例实际使用的 `plugins/` 目录，确保 `plugin.py`、`_manifest.json`、`config.toml` 在同一层。
2. 沿用 MaiBot 的运行环境，确保其中有 `maibot-plugin-sdk==2.16.0` 和 `tomlkit>=0.13.3`。如宿主支持 ZIP 安装，也可以使用原生插件管理页首次安装。
3. 重载并启用插件。包内默认配置已包含版本号，默认启用。
4. 在日志中确认 `稳定身份插件已加载 v0.2.6`，再按下文检查实际模型请求。

Docker 部署需要把文件放入实际映射到容器插件目录的位置，不能只放到容器无法访问的本地目录。

### 已有安装升级

先备份个人 `config.toml`，再更新现有插件目录中的代码和文档，**保留个人配置**。WebUI 安装后的目录可能叫 `local_stable-identity/`，应更新这个现有目录，避免同时保留两个相同插件 ID的副本。

配置结构仍为 `0.1.0`，与插件发布版本不同，不需要迁移聊天或记忆数据。如遇到“缺少 plugin.config_version”，按 [安装与配置修复说明](INSTALL_ZIP.md)补齐；修复工具会先备份，只补缺失版本。

源码、发布包及问题反馈见 [GitHub 仓库](https://github.com/ZeroBlock0/maibot-stable-identity)和 [Releases](https://github.com/ZeroBlock0/maibot-stable-identity/releases)。插件 ID 保持不变，已有安装无需更换配置目录。

## 配置

默认配置如下，可在宿主插件配置页或现有 `config.toml` 中调整：

```toml
[plugin]
enabled = true
config_version = "0.1.0"

[limits]
cache_capacity = 4096
cache_ttl_seconds = 600
concurrency = 8
scan_limit = 1000
result_limit = 20
```

`scan_limit` 限制单次范围查询扫描的消息数，`result_limit` 限制返回证据条数。缓存、查询并发及输出均有上限；超时或无法核实时返回未知或查询失败，保留原生聊天。配置热更新会清空插件自己的缓存和短期查证凭据。

## 聊天身份如何判断

插件只处理宿主生成的消息边界，并回查宿主记录，核对平台、账号、路由、会话、时间、消息 ID及当时昵称等元数据。可靠对应且候选唯一时，才添加稳定身份；无法确认时标记为 `unknown`。

下面是省略其他属性后的合成示意，两个同名用户仍是不同账号：

```text
<message user="小明" sender_id="qq:1001">
我在杭州工作。

<message user="小明" sender_id="qq:1002">
我在成都工作。
```

实际请求保留原有消息 ID、时间、名片、机器人标记和引用属性。`sender_id` 直接表示平台与真实账号，不是按昵称产生的新编号；分隔符等特殊字符使用百分号编码。只有已核验消息才带此字段，未核验时只有 `identity_status="unknown"`。

已核验账号能通过人物接口关联时，按消息顺序在该账号首次取得可靠映射的消息上附 `person_id`，同一请求内后续消息不重复它。每次请求独立重建，不依赖上次请求或旧标注。正文里自写的 `sender_id`、`person_id` 或旧版标签不能改变外层身份；引用和转发内容也不等于发送者本人的经历。

安装前历史和重启后的历史可以重新回查，但前提是宿主仍保存足够的原始记录。缺少记录、短 ID映射冲突、归属不一致或超时，均不能按昵称或最近发言者补猜。

## 原话查证工具

模型可调用 `stable_identity_lookup_original_messages`，用于核实“谁说过什么”。

| 查询条件 | 用途 |
|---|---|
| `sender_user_id` | 按真实用户 ID筛选，不能填昵称 |
| `person_id` | 按宿主稳定人物 ID筛选；与账号同时填写时必须一致 |
| `keyword` | 在发言人本人的原始文字中精确搜索 |
| `start_time` / `end_time` | 带时区的 ISO 8601 时间或 Unix 秒字符串 |
| `message_id` | 查询单条原始 ID或本次上下文中有可靠映射的显示 ID |
| `message_ids` | 批量查询 1–12 个来源 ID，不能与单条 ID同时填写 |
| `limit` | 返回数量，受插件配置上限约束 |

不按 ID查询时，默认检索最近七天并优先返回最新匹配；按 ID查询默认不限时间，也可以叠加其他筛选。显式填写空白 `message_id` 会被拒绝，不会变成范围查询。

工具返回原始发言人的账号、当时昵称/名片、时间、消息 ID、本人原文及消息段类型。机器人发言单独标注；引用只保留未核验的引用 ID，不展开群外内容；合并转发不作为转发者原话；图片描述和语音转写明确与用户原始文字区分。

查询只能使用本次请求绑定的会话，模型不能自行切换群聊、私聊或机器人账号。缺少有效上下文、凭据过期或重放时拒绝执行。默认最多扫描 1000 条、返回 20 条，证据输出预算为 32000 字符；实际有遗漏时返回 `incomplete=true`。这表示检索不完整，不能据此断言历史中从未说过某件事。

## 长期记忆：哪些已接通，哪些仍有限制

**聊天消息有账号 ID，不等于每条记忆摘要也保存了人物归属和原始来源。** 原始聊天、人物事实、群聊摘要和画像是不同层的数据。群聊摘要可能合并多人发言；没有人物与来源字段时，不能把整段摘要归给当前提问者。

插件目前接通了以下部分：

- 把已核验账号关联到宿主 `person_id`，供支持该参数的原生画像工具及本插件原话工具使用。
- 回查当前上下文中 `query_memory`、`query_person_profile` 对应的正式 `ToolRecord`。有完整结构时，逐条核对实际主体、当前会话与原始来源；查询目标不会直接被当成每条命中的主体。
- Planner 得到核验结果后，可以在原生 `reply_reference` 中保留插件给出的来源引用；Replyer 收到这个引用后，会重新回查同一记录。

### “自动透传仍有限制”是什么意思

Planner 负责判断和选择参考资料，Replyer 负责生成最终回复。原生流程不会把 Planner 的全部工具结果直接交给 Replyer，插件目前依赖模型保留来源引用。

**如果 Planner 漏传引用，Replyer 就无法得到对应记忆的完整核验说明。** 没有明确引用或原生记忆工具结果时，不再向模型追加 `reference_missing` 或记忆规则；非空参考缺引用只在日志中诊断，也不会使用“本群最近一次记忆查询”。原生参考保持原样，插件没有认证其人物归属。

普通聊天没有记忆工具结果或明确引用时，不追加任何记忆核验文本，也不回查工具记录。真实工具结果或明确引用仍按条核验，保留未知主体与来源边界；本版没有关闭记忆增强功能。

此外，自动画像注入、纯文本回想、部分压缩资料和旧摘要，可能没有足够的主体或来源字段。原生记忆检索也可能在人物筛选无匹配时返回其他候选，因此“按某人的名字搜到了”并不能证明结果属于那个人。

这就是当前限制：**聊天身份标注、原话查证及部分记忆来源核验已经可用；每次回忆都自动带齐人物 ID和来源的完整链路尚未实现。** 不应承诺既有错误记忆会因此自动恢复正确。

### 可选的宿主设置

宿主的以下设置决定今后的工具记录是否保存完整结构：

```toml
[debug]
record_tool_structured_content = true
```

插件不会自动修改此设置。开启后宿主会保存更完整的工具结果，可能包含记忆正文和来源信息；它只影响后续记录，不会补回旧记录中已经省略的字段。不开启时，聊天身份标注和原话工具仍然可用。

画像工具目前只能核对其报告的人物 ID映射，不能提供它没有暴露的逐条原话证据。更多接口与来源边界见 [记忆核验说明](docs/MEMORY_BRIDGE.md)。

## 如何确认生效

1. 筛选日志 `plugin.local.stable-identity` 或 `身份增强`，确认版本与 Planner、Replyer 的标注计数。活动摘要每阶段首次输出，之后限频到每 60 秒；日志不打印账号、原文或凭据。
2. 查看最终模型请求，确认宿主生成的已核验消息前缀包含 `sender_id="平台:真实账号"`；人物映射按账号只出现一次 `person_id`。Planner 和 `maisaka.replyer` 应分别检查。普通无参考聊天应没有 `stable_identity.memory` 文本。
3. 核对没有宿主“items 无效/无法反序列化，已忽略”等告警。仅有“标注完成”或模型自称“认识你”，不足以证明最终请求已接收增强。

记忆相关状态含义：

| 状态 | 含义 |
|---|---|
| `source_identity_verified` | 来源消息的发言人身份与记录主体一致；不证明事实或语义提取正确 |
| `subject_unknown` | 无法认证主体，具体 `reason` 说明缺失层 |
| `structured_omitted` | 宿主没有保留完整结构，不能从可读摘要补出来源 |
| `reference_missing` | 仅日志诊断：非空参考没有明确核验引用，插件未核验来源；不注入模型请求 |
| `incomplete` | 原话检索确有扫描、输出或来源完整性限制，不能当成完整历史结论 |

## 模式支持

| 模式 | 当前范围 |
|---|---|
| 普通 Planner / Replyer | 对上下文内能准确回查的真实消息逐条补身份 |
| Focus Planner | 根据宿主逐条提供的会话来源核验；没有可靠来源时保持未知 |
| Focus 原话查证 | 共享 Hook 没有唯一授权会话，新增工具拒绝执行 |
| 复古 Replyer | 不改写无逐条 ID的历史模板，仅补充明确回复目标的身份参考 |
| 上下文压缩 | 已增强快照可以继承；另外追加、绕过 Hook 的资料不保证覆盖 |
| 自动记忆、画像学习及摘要 | 原生流程保留；不保证每项内容自动获得可靠身份与来源 |

原生 Focus 工具、图片、表情、引用及其他插件上下文不会被本插件主动删除或替换。此处说明的是当前实现范围，不代表所有第三方组合已经完成在线兼容测试。

## 数据保存、停用与卸载

身份标记包含真实平台账号及宿主人物 ID，会随聊天请求发送给宿主配置的模型服务。本地映射不额外调用模型，但不意味着这些 ID 只留在插件内存中。启用前应按实际群聊和模型服务的数据使用要求安排部署。

插件配置保存在 `config.toml`。身份映射、来源引用、计数与执行凭据只存在于有容量和过期限制的内存缓存中；重启、重载或卸载后清空，再从宿主回查。插件不另建聊天或记忆数据库，不批量修改旧记忆。

宿主原有的聊天、画像、记忆和工具记录仍由宿主保存。若开启请求快照或推理记录，含身份标记的模型请求也可能由宿主落盘；这不等于身份已写入每条长期记忆。

在原生插件管理页停用并重载即可停止增强。卸载时删除现有插件目录，需保留配置时先备份 `config.toml`。无需清理宿主表、迁移记忆或停止额外服务；已保存的宿主请求快照按原生机制保留，不会被卸载操作批量删除。
